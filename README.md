## 🌊 The Problem

> When disaster strikes, **two things fail together** — infrastructure and the communication networks people depend on to ask for help.

Cell towers become overloaded or collapse. Victims struggle to reach emergency responders. Response teams lose visibility into who needs assistance, where they are, and how urgently they need it.

Most disaster-response applications assume reliable internet connectivity — precisely the assumption that fails during emergencies.

**RapidAID is designed around a different reality: connectivity cannot be guaranteed when lives are at stake.**

## ⚡ The Idea

<div align="center">

### One platform. Two AI environments. Continuous response.

```text
           NO SIGNAL                  SIGNAL RETURNS
      ┌──────────────────┐        ┌────────────────────┐
      │                  │        │                    │
      │   ⚡ GEMINI NANO  │        │   ☁ CLOUD GEMINI   │
      │                  │        │                    │
      │  On-device AI    │        │  Advanced analysis │

      │  Local processing│        │  Smart summaries  │
      │                  │        │                    │
      └────────┬─────────┘        └─────────┬──────────┘
               │                            │
               ▼                            ▼
        📦 LOCAL QUEUE  ──────────────►  🔥 FIRESTORE
               │                            │
               ▼                            ▼
        INSTANT RESPONSE               CLOUD ENHANCED
```

</div>

RapidAID processes emergency reports locally using **Gemini Nano on supported devices**, providing immediate classification and triage without requiring a cloud connection.

When connectivity becomes available, reports synchronize with Firebase, where **Cloud Gemini through Firebase AI Logic** can perform more complex analysis, identify duplicate reports, enrich cases, and generate summaries.

This isn't hybrid AI merely as an optimization. It's hybrid AI as the foundation of the entire system.

Because during a disaster, offline operation isn't an edge case — it's a necessity.

## 🧭 How It Works

<div align="center">

<img width="380" height="508" alt="RapidAID Emergency Response Workflow" src="https://github.com/user-attachments/assets/63bc51cd-eee7-432c-b78d-1790243cbb3b" />


</div>

### The workflow

1. **Report:** Users submit an emergency report through text, voice, or the SOS button.
2. **Analyze:** On-device AI identifies the emergency category and urgency.
3. **Confirm:** The application provides immediate local feedback.
4. **Store:** Reports are added to the local offline queue.
5. **Synchronize:** Stored reports are uploaded when connectivity returns.
6. **Enhance:** Cloud AI processes complex reports and identifies potential duplicates.
7. **Coordinate:** Medical and rescue teams receive updated, prioritized information.
8. **Track:** Users can follow the progress of their submitted reports.

## 🛰️ Why Hybrid AI?

RapidAID combines local intelligence with cloud-based reasoning to maintain functionality across different connectivity conditions.

<div align="center">

| Capability | ⚡ On-device AI | ☁️ Cloud AI |
|:---|:---:|:---:|
| Works without internet | ✅ | ❌ |
| Instant local processing | ✅ | — |
| Emergency classification | ✅ | ✅ |
| Urgency identification | ✅ | ✅ |
| Complex multi-report analysis | Limited | ✅ |
| Duplicate report merging | Limited | ✅ |
| Cross-report summarization | ❌ | ✅ |
| Cloud-wide coordination | ❌ | ✅ |

</div>

### ⚡ On-device Intelligence

- Processes supported emergency inputs locally.
- Provides immediate classification and urgency tagging.
- Reduces dependency on network availability.
- Keeps basic triage available during connectivity failures.

### ☁️ Cloud Intelligence

- Analyzes complex or ambiguous reports.
- Identifies potential duplicate submissions.
- Combines related emergency information.
- Generates structured case summaries.
- Supports centralized responder coordination.

**Every report can display its processing state — ⚡ On-device or ☁ Cloud-enhanced — making the hybrid architecture visible to users and responders.**

## 🏗️ System Architecture

<img width="1600" height="900" alt="rapidaid_architecture_workflow" src="https://github.com/user-attachments/assets/04aa2724-d6f3-4d92-ab38-b00aa4dc18ec" />


### Architecture principles

- **Offline-first:** Core reporting functionality remains accessible without internet connectivity.
- **Hybrid intelligence:** Local and cloud inference serve different processing requirements.
- **Real-time synchronization:** Firestore distributes updates to connected dashboards.
- **Role-based access:** Users, medical personnel, and rescue teams receive appropriate permissions.
- **Resilient coordination:** Locally stored reports can synchronize when a connection becomes available.

## 🚀 Getting Started

Follow these steps to run RapidAID locally.

### 1. Clone the repository

```bash
git clone https://github.com/<your-org>/rapidaid.git

cd rapidaid
```

### 2. Install dependencies

```bash
npm install
```

### 3. Configure environment variables

Create a `.env.local` file in the project root.

```env
NEXT_PUBLIC_FIREBASE_API_KEY=your_api_key
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your_project_id
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=your_project.firebasestorage.app
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
NEXT_PUBLIC_FIREBASE_APP_ID=your_app_id
```

Add any additional environment variables required by your implementation.

### 4. Start the development server

```bash
npm run dev
```

Open your browser:

```text
http://localhost:3000
```

### 5. Build for production

```bash
npm run build
```

## 🧯 Scope & Responsible Use

RapidAID is designed as an **emergency information routing and coordination platform for human responders**.

It does not:

- Make autonomous medical decisions.
- Replace doctors, emergency personnel, or rescue professionals.
- Guarantee that emergency assistance will arrive.
- Replace official emergency communication channels.
- Treat AI-generated urgency classifications as verified medical diagnoses.

AI-generated classifications and summaries are intended to assist human responders, not replace their professional judgment.

All demonstration data should be simulated. Do not publish real victim information, private location data, or sensitive emergency records in the repository or demo video.
